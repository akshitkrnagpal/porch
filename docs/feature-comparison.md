The audit used the source checkout at `/tmp/porch-portless-reference`, including behavior added after the installed Portless skill: Compose, Cloudflare, MCP, worktree templates, and unprivileged binding.

This is a capability inventory, not a claim of complete Portless parity or daily-use readiness. The independent review at `8030fdb` found P0/P1 blockers despite the previous passing tests; its original assessment is preserved in [the review](reviews/opus-2026-11-06.md), with subsequent [fix evidence and remaining limits](remediation-2026-11-06.md). The implementation supports the workflows below at the stated verification boundaries. Evidence distinguishes real local socket/process acceptance from fake external command tests. An OS template or fake CLI test does not establish that a privileged operation or authenticated external service works on every target machine.

## Deliberate compatibility choices

Porch uses its own executable, state directory (`~/.porch`), service identity, and managed hosts markers. It reads the upstream configuration shape and public `PORTLESS_*` settings; corresponding `PORCH_*` variables take precedence. State files and internal hosts-authentication protocol are Porch-owned and are not a shared on-disk format with a running Portless daemon. A root workspace name sets the project domain without renaming every package to the same hostname; leaf app overrides remain authoritative.

The CLI adds `list --json`, route removal/list aliases, explicit bind/redirect overrides, and URL upstream aliases. HTTPS is the default; `--unprivileged` defaults to plain HTTP unless HTTPS is explicitly chosen. In unattended sessions, a newly created untrusted CA produces a descriptive error rather than an OS prompt. Automated clients can load the CA directly and use `--skip-trust`.

Passing local acceptance does not establish parity or remove external verification boundaries. Terminal job control, first-run elevation, collision policy, config resolution and TLS issuance now have regressions that failed on the reviewed implementation and passed after remediation.

## Verification record

See [the remediation record](remediation-2026-11-06.md) for exact commands, regression failures, final counts and native CI results for this revision. Previous 68/69-test runs and native CI applied to earlier commits and missed terminal job-control, sudo, collision and config/TLS policy failures. They are not evidence that those releases were ready for daily use.

Supported build targets are `aarch64-apple-darwin` and `x86_64-unknown-linux-gnu`; Windows is deferred. Real privileged trust/service installation, live Docker/tunnel providers and physical LAN transitions remain unverified. Existing trusted CA identity/validity is preserved; application-level issuance policy is restricted, while the root has no DNS NameConstraints. The browser rejection hypothesis in the independent review remains unproven.

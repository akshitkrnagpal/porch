## Deliberate compatibility choices

Porch uses its own executable, state directory (`~/.porch`), service identity, and managed hosts markers. It reads the upstream configuration shape and public `PORTLESS_*` settings; corresponding `PORCH_*` variables take precedence. State files and internal hosts-authentication protocol are Porch-owned and are not a shared on-disk format with a running Portless daemon. A root workspace name sets the project domain without renaming every package to the same hostname; leaf app overrides remain authoritative.

The CLI adds `list --json`, route removal/list aliases, explicit bind/redirect overrides, and URL upstream aliases. HTTPS is the default; `--unprivileged` defaults to plain HTTP unless HTTPS is explicitly chosen. In unattended sessions, a newly created untrusted CA produces a descriptive error rather than an OS prompt. Automated clients can load the CA directly and use `--skip-trust`.

The preceding implementation's missing auto-start, URL lookup, option parser, identity/cleanup, dual-stack, loop detection, TLS redirect, Node CA, extended CONNECT, workspace, authenticated hosts, Windows service, and tunnel/Compose lifecycle paths are implemented and covered at the boundaries listed above. Completion of local acceptance does not remove the external verification boundaries.

## Verification record

Acceptance runs isolate state and never modify this machine's real hosts file, trust store, or startup services. Final integrated local acceptance: **68 tests passed** on macOS ARM64 (27 unit, 12 CLI, 13 config/workspace, 10 external-integration fixtures, 5 lifecycle regressions, 1 comprehensive network acceptance). `cargo fmt --all -- --check` and `cargo clippy --all-targets -- -D warnings` passed. The tests include concurrent auto-start/port reservations, immediate signal cleanup after registration, fixed-port takeover with delayed/ignored signals, orphaned grandchildren, browser-blocked ports, stale pool recovery, scoped alias removal, self-daemon route transfer, and Node-to-Node local CA trust.

Native Windows execution, privileged trust/startup installation, live Docker/provider accounts, and physical LAN transitions remain external verification boundaries, as detailed above. No real machine hosts/trust/startup resources were modified.

Release validation: `cargo build --release` passed. The isolated release-binary smoke ran bare package mode with automatic HTTPS startup, verified the generated CA using Python/OpenSSL `VERIFY_X509_STRICT`, checked public `get` and JSON list output and child PORT/HOST/URL/CA variables, confirmed SIGTERM exit 143 and route cleanup, restarted through app launch, preserved child exit 37, and stopped the proxy. Binary: `target/release/porch` (macOS ARM64).

## Independent handoff checks

The parent agent reran all 68 local tests, formatting and strict Clippy, verified the private remote and matching commit, and rebuilt the release executable. Native macOS and Linux CI have passed the acceptance suite. A separately installed Turbo 2.11.10 ran a two-package npm workspace through Porch, with distinct assigned ports and correct public URLs. Windows socket exclusivity and case-insensitive Turbo manifest lookup received portability fixes after native CI exposed them. Windows was explicitly deferred by the user and removed from the supported CI/release matrices. Its code remains experimental.

Supported binary targets for this release: `aarch64-apple-darwin` and `x86_64-unknown-linux-gnu`. Windows is deferred. Core native macOS/Linux tests run in CI; real privileged trust/service installation, live tunnel providers and physical LAN transitions remain unverified.
